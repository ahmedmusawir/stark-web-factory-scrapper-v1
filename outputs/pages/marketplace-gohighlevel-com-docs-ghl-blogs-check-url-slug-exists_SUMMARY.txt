Here's a structured summary of the API documentation:

### 1. ENDPOINT NAME:
Check url slug

### 2. CATEGORY:
Blogs

### 3. HTTP METHOD:
GET

### 4. ENDPOINT URL:
`/blogs/posts/url-slug-exists`

### 5. FULL URL:
`https://services.leadconnectorhq.com/blogs/posts/url-slug-exists`

### 6. REQUIRED PARAMETERS:
*   **Header Parameters:**
    *   `Version` (string): API Version. Possible values: [`2021-07-28`]
*   **Query Parameters:**
    *   `urlSlug` (string): The URL slug to check for existence.
    *   `locationId` (string): The ID of the location (sub-account) to check within. Example: `ve9EPM428h8vShlRW1KT`

### 7. OPTIONAL PARAMETERS:
*   **Query Parameters:**
    *   `postId` (string): The ID of the blog post to exclude from the check (used when updating an existing post). Example: `66f429b8afdce84227a4610d`

### 8. AUTHENTICATION:
*   **Scope(s):** `blogs/check-slug.readonly`
*   **Auth Method(s):** `OAuth Access Token`, `Private Integration Token`
*   **Token Type(s):** `Sub-Account Token`
*   **Scheme:** Bearer (JWT) in the `Authorization` header.
*   **Description:** Use the Access Token generated with user type as Sub-Account (OR) Private Integration Token of Sub-Account.

### 9. RESPONSE FORMAT:
*   **200 OK (Successful response):**
    *   `application/json`
    *   **Schema:**
        *   `exists` (boolean): Indicates whether the url slug exists or not.
    *   **Example:**
        ```json
        {"exists": true}
        ```
*   **400 Bad Request:**
    *   `application/json`
    *   **Schema:** `statusCode` (number), `message` (string)
    *   **Example:** `{"statusCode":400,"message":"Bad Request"}`
*   **401 Unauthorized:**
    *   `application/json`
    *   **Schema:** `statusCode` (number), `message` (string), `error` (string)
    *   **Example:** `{"statusCode":401,"message":"Invalid token: access token is invalid","error":"Unauthorized"}`
*   **422 Unprocessable Entity:**
    *   `application/json`
    *   **Schema:** `statusCode` (number), `message` (string[]), `error` (string)
    *   **Example:** `{"statusCode":422,"message":["Unprocessable Entity"],"error":"Unprocessable Entity"}`

### 10. PURPOSE:
This API allows checking the validation of a blog URL slug, which is necessary before publishing any blog post.

### 11. TAGS:
Blogs, URL slug, validation, check, read-only, GET, post, existence.

**Code Examples Availability:**
cURL, nodejs, python, php, java, go, ruby, powershell. A cURL example is provided in the documentation.
