Here is the structured summary of the API documentation:

### 1. ENDPOINT NAME:
List active numbers

### 2. CATEGORY:
Phone System

### 3. HTTP METHOD:
GET

### 4. ENDPOINT URL:
`/phone-system/numbers/location/:locationId`

### 5. FULL URL:
`https://services.leadconnectorhq.com/phone-system/numbers/location/:locationId`

### 6. REQUIRED PARAMETERS:
*   **Version (string)**: API Version. Possible values: `2021-07-28`
*   **locationId (string)**: The unique identifier of the location. Example: `ve9EPM428h8vShlRW1KT`

### 7. OPTIONAL PARAMETERS:
*   **pageSize (number)**: How many resources to return in each list page. The default is 50, and the maximum is 1000. Default value: `1000`. Possible values: `>= 1` and `<= 1000`. Example: `100`
*   **page (number)**: The page index for pagination. The default is 0. Default value: `0`. Example: `0`
*   **searchFilter (string)**: Filter numbers by phone number pattern. Supports partial matching (e.g., "+91" to find all Indian numbers). Example: `+91`
*   **skipNumberPool (boolean)**: Whether to exclude numbers that are assigned to number pools. Default is true. Default value: `true`. Example: `true/false`

### 8. AUTHENTICATION:
*   **Scope(s)**: `phonenumbers.read`
*   **Auth Method(s)**: `OAuth Access Token`, `Private Integration Token`
*   **Token Type(s)**: `Sub-Account Token`
*   **Scheme**: `bearer`
*   **Bearer Format**: `JWT`
*   **In**: `header`

**Content Type**: `application/json`

### 10. PURPOSE:
This endpoint retrieves a paginated list of active phone numbers for a specific location, supporting filtering, pagination, and optional exclusion of number pool assignments.
