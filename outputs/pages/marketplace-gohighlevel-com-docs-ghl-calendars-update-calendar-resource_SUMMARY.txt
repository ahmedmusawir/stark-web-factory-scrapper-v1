Here is a structured summary of the "Update Calendar Resource" API documentation:

### 1. ENDPOINT NAME:
Update Calendar Resource

### 2. CATEGORY:
Calendars

### 3. HTTP METHOD:
PUT

### 4. ENDPOINT URL:
`/calendars/resources/:resourceType/:id`

### 5. FULL URL:
`https://services.leadconnectorhq.com/calendars/resources/:resourceType/:id`

### 6. REQUIRED PARAMETERS:

*   **Header Parameters:**
    *   `Version` (string): API Version. Possible values: `2021-04-15`

*   **Path Parameters:**
    *   `resourceType` (string): Calendar Resource Type. Possible values: `equipments`, `rooms`
    *   `id` (string): Calendar Resource ID

*   **Body Parameters:**
    *   `locationId` (string): Location ID of the resource.
    *   `name` (string): Name of the resource.
    *   `isActive` (boolean): Whether the resource is active.

### 7. OPTIONAL PARAMETERS:

*   **Body Parameters:**
    *   `description` (string): Description of the resource.
    *   `quantity` (number): Quantity of the equipment.
    *   `outOfService` (number): Quantity of the out of service equipment.
    *   `capacity` (number): Capacity of the room.
    *   `calendarIds` (string[]): Service calendar IDs to be mapped with the resource. Possible values: `<= 100`.
        *   *Note*: One equipment can only be mapped with one service calendar. One room can be mapped with multiple service calendars.

### 8. AUTHENTICATION:

*   **Scope(s):** `calendars/resources.write`
*   **Auth Method(s):** `OAuth Access Token`, `Private Integration Token`
*   **Token Type(s):** `Sub-Account Token`
*   **Scheme:** `bearer`
*   **Bearer Format:** `JWT`
*   **In:** `header`
*   **Description:** Use the Access Token generated with user type as Sub-Account (OR) Private Integration Token of Sub-Account.

### 9. RESPONSE FORMAT:

*   **Successful Response (200 OK):**
    *   **Description:** Calendar resource updated
    *   **Content Type:** `application/json`
    *   **Schema:**
        *   `locationId` (string, required): Location ID of the resource. Example: `"string"`
        *   `name` (string, required): Name of the resource. Example: `"yoga room"`
        *   `resourceType` (string, required): Possible values: `equipments`, `rooms`
        *   `isActive` (boolean, required): Whether the resource is active.
        *   `description` (string, optional): Description of the resource. Example: `"string"`
        *   `quantity` (number, optional): Quantity of the resource. Example: `0`
        *   `outOfService` (number, optional): Indicates if the resource is out of service. Example: `0`
        *   `capacity` (number, optional): Capacity of the resource. Example: `85`
    *   **Example:**
        ```json
        {"locationId":"string","name":"yoga room","resourceType":"equipments","isActive":true,"description":"string","quantity":0,"outOfService":0,"capacity":85}
        ```

*   **Error Responses:**
    *   **400 Bad Request:**
        *   Schema: `{"statusCode": number, "message": string}`
        *   Example: `{"statusCode":400,"message":"Bad Request"}`
    *   **401 Unauthorized:**
        *   Schema: `{"statusCode": number, "message": string, "error": string}`
        *   Example: `{"statusCode":401,"message":"Invalid token: access token is invalid","error":"Unauthorized"}`

### 10. PURPOSE:
This endpoint is used to update an existing calendar resource (either an equipment or a room) by its ID within a specified location.
