Here is a structured summary of the NoteUpdate Webhook documentation:

### 1. ENDPOINT NAME:
NoteUpdate

### 2. CATEGORY:
Webhook

### 3. HTTP METHOD:
POST (This is the method HighLevel uses to send the webhook payload to a configured URL)

### 4. ENDPOINT URL:
Not applicable (This is a webhook payload description; HighLevel posts this payload to a user-defined URL configured for webhooks.)

### 5. FULL URL:
`https://marketplace.gohighlevel.com/docs/webhook/NoteUpdate/index.html` (This is the documentation URL, not an API endpoint to call)

### 6. REQUIRED PARAMETERS (Payload Fields):
*   **type** (string): The type of webhook event, which is "NoteUpdate".
*   **locationId** (string): The unique identifier of the sub-account (formerly location) where the note was updated.
*   **id** (string): The unique identifier of the updated note.
*   **body** (string): The updated content or text of the note.
*   **contactId** (string): The unique identifier of the contact associated with the note.
*   **dateAdded** (string): The timestamp when the note was added or, in the context of an update, likely the timestamp of the last update in ISO 8601 format (e.g., `YYYY-MM-DDTHH:mm:ss.sssZ`).

### 7. OPTIONAL PARAMETERS:
Not specified in documentation (All fields in the schema are present in the example payload.)

### 8. AUTHENTICATION:
Not specified in documentation (For receiving webhooks, generally no specific authentication is performed by the sender on the receiver's end, though the receiving server might validate the request using signatures or shared secrets if configured.)

### 9. RESPONSE FORMAT:
The documentation describes the **payload format** that HighLevel sends when a NoteUpdate event occurs. The receiving server is expected to return an HTTP success status (e.g., 200 OK) to acknowledge receipt.

**Example Payload (JSON):**
```json
{
  "type": "NoteUpdate",
  "locationId": "ve9EPM428h8vShlRW1KT",
  "id": "otg8dTQqGLh3Q6iQI55w",
  "body": "Loram ipsum",
  "contactId": "CWBf1PR9LvvBkcYqiXlc",
  "dateAdded": "2021-11-26T12:41:02.193Z"
}
```

### 10. PURPOSE:
This webhook is triggered and sends a payload to a configured endpoint whenever an existing note within the HighLevel system is updated.
