Here is the structured summary of the API documentation:

### 1. ENDPOINT NAME
Check if account has sufficient funds

### 2. CATEGORY
Developer marketplace (Wallet Charges)

### 3. HTTP METHOD
GET

### 4. ENDPOINT URL
`/marketplace/billing/charges/has-funds`

### 5. FULL URL
`https://services.leadconnectorhq.com/marketplace/billing/charges/has-funds`

### 6. REQUIRED PARAMETERS
Not specified in documentation (The GET request itself does not take path, query, or body parameters.)

### 7. OPTIONAL PARAMETERS
Not specified in documentation

### 8. AUTHENTICATION
*   **Scope(s):** `charges.readonly`
*   **Auth Method(s):** `OAuth Access Token`
*   **Token Type(s):** `Sub-Account Token`
*   **Authorization Details:**
    *   **name:** Authorization
    *   **type:** http
    *   **scheme:** bearer
    *   **bearerFormat:** JWT
    *   **in:** header
    *   **description:** Use the Access Token generated with user type as Sub-Account.

### 9. RESPONSE FORMAT

**200 OK - Returns fund availability status**
*   **Content Type:** `application/json`
*   **Schema:**
    *   `hasFunds` (boolean): Indicates if the account has sufficient funds.
*   **Example:**
    ```json
    {"hasFunds": true}
    ```

**422 Unprocessable Entity**
*   **Content Type:** `application/json`
*   **Schema:**
    *   `statusCode` (number): The HTTP status code. Example: `422`
    *   `message` (string[]): An array of error messages. Example: `["Unprocessable Entity"]`
    *   `error` (string): A general error description. Example: `Unprocessable Entity`
*   **Example:**
    ```json
    {"statusCode": 422, "message": ["Unprocessable Entity"], "error": "Unprocessable Entity"}
    ```

### 10. PURPOSE
This endpoint allows you to check if a specific Sub-Account has sufficient funds available for potential charges.
