Here is the structured summary of the API documentation:

**1. ENDPOINT NAME:** Get Action by ID

**2. CATEGORY:** Conversation AI Actions

**3. HTTP METHOD:** GET

**4. ENDPOINT URL:** `/conversation-ai/agents/:agentId/actions/:actionId`

**5. FULL URL:** `https://services.leadconnectorhq.com/conversation-ai/agents/:agentId/actions/:actionId`

**6. REQUIRED PARAMETERS:**
*   `Version` (string): API Version (Possible values: `2021-04-15`). Sent in Header.
*   `actionId` (string): The unique identifier of the action ID Attached to the agent. Sent in Path.
*   `agentId` (string): The unique identifier of the agent. Sent in Path.

**7. OPTIONAL PARAMETERS:**
Not specified in documentation

**8. AUTHENTICATION:**
*   **Scope(s):** `conversation-ai.readonly`
*   **Auth Method(s):** `OAuth Access Token`, `Private Integration Token`
*   **Token Type(s):** `Sub-Account Token`

**9. RESPONSE FORMAT:**
*   **Status Code:** `200 OK`
*   **Content Type:** `application/json`
*   **Structure:**
    *   `data` (object): Contains the detailed action information.
        *   `id` (string): Unique identifier for the action.
        *   `name` (string): Name of the action.
        *   `type` (string): Type of the action (e.g., `triggerWorkflow`, `updateContactField`, `appointmentBooking`, `stopBot`, `humanHandOver`, `advancedFollowup`, `transferBot`).
        *   `agentId` (string): Agent ID where the action belongs.
        *   `details` (object): Action-specific details, whose structure varies based on the `type` field (e.g., `triggerWorkflowDto`, `updateContactFieldDto`, etc.).
    *   `success` (boolean): Indicates the success status of the request (`true` for success).

**10. PURPOSE:** Retrieves detailed information about a specific action using its unique identifier, returning the action's configuration, associated agents, and performance metrics.

**11. TAGS:** Conversation AI, Actions, Agent Actions, Get, Retrieve, Action Details, Readonly, HighLevel API
