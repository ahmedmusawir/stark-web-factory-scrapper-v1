**6. REQUIRED PARAMETERS:**
    These are **App Configuration Settings** for the Marketplace app itself, not parameters for a direct API call described in this document.
    *   **Who is the target user of the app?** (string: `Agency` / `Sub-account`): Defines whose access token the app ultimately needs. Cannot be modified once set.
    *   **Who can install the app?** (string: `Both Agency and Sub-account` / `Agency Only`): Determines which user(s) can see and install the app from the Marketplace UI.
    *   **Can this app be bulk-installed by agencies?** (string: `Yes` / `No`): Allows agency owners/admins to install to multiple sub-accounts in one operation. All new Marketplace apps are set to `Yes` (mandatory) and cannot revert to `No`.

    **Properties of received Access Token** (not parameters sent, but important for understanding the token):
    *   **isBulkInstallation** (boolean): Indicates if the installation was a bulk operation.
    *   **userType** (string: `Company` / `Location`): Identifies the user type associated with the access token (`Company` for Agency, `Location` for Sub-account).

**7. OPTIONAL PARAMETERS:** Not specified in documentation (for API calls).

**8. AUTHENTICATION:**
    *   **Method:** OAuth 2.0 flow.
    *   **Token Types:** Access tokens are obtained, specifically Agency-level tokens (for `Company` userType) and Sub-account-level tokens (for `Location` userType). The document describes a process to obtain Location Tokens using an Agency Token.
    *   **Scopes:** Not explicitly listed as required for this distribution model itself. However, the "Backward Compatibility" section mentions agency-level scopes to avoid if targeting sub-accounts (e.g., `companies.readonly`, `companies.write`, `location.write`, `saas/location.write`, `snapshots.readonly`, `snapshots.write`, `custom-menu-link.readonly`, `custom-menu-link.write`). The specific scopes required for an app would depend on its functionality and the API resources it needs to access.

**9. RESPONSE FORMAT:** The document does not provide a full response format for an API call. It only details specific properties found within an access token payload (`isBulkInstallation`, `userType`).

**10. PURPOSE:** This guide covers the new, simplified Marketplace app distribution model and the OAuth flow developers need to implement to obtain the correct access tokens based on their app's configuration and target users.
