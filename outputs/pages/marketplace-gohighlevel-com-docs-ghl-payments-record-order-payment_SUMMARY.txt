Here is a structured summary of the API documentation for "Record Order Payment":

### 1. ENDPOINT NAME:
Record Order Payment

### 2. CATEGORY:
Payments > Orders

### 3. HTTP METHOD:
POST

### 4. ENDPOINT URL:
`/payments/orders/:orderId/record-payment`

### 5. FULL URL:
`https://services.leadconnectorhq.com/payments/orders/:orderId/record-payment`

### 6. REQUIRED PARAMETERS:

*   **Header Parameters:**
    *   `Version` (string): API Version (Possible values: `2021-07-28`)
*   **Path Parameters:**
    *   `orderId` (string): Order ID (Example: `5e2d4c8e0e8b4e001c1c4f5d`)
*   **Body Parameters:**
    *   `altId` (string): location Id / company Id based on altType (Example: `6578278e879ad2646715ba9c`)
    *   `altType` (string): Alt Type (Possible values: `location`) (Example: `location`)
    *   `mode` (string): manual payment method (Possible values: `cash`, `card`, `cheque`, `bank_transfer`, `other`) (Example: `card`)
    *   `card.type` (string): (Required if `mode` is `card`) Possible values: `visa`, `mastercard`, `other` (Example: `mastercard`)
    *   `card.last4` (string): (Required if `mode` is `card`) Last 4 digit of the card (Example: `1234`)
    *   `cheque.number` (string): (Required if `mode` is `cheque`) check number (Example: `129-129-129-912`)

### 7. OPTIONAL PARAMETERS:

*   **Body Parameters:**
    *   `card` (object): Details of Card if used for payment (This object is optional, but if included, its internal fields `type` and `last4` become required)
    *   `cheque` (object): Details of the Cheque if used for payment (This object is optional, but if included, its internal field `number` becomes required)
    *   `notes` (string): Any note to be recorded with the transaction (Example: `This was a direct payment`)
    *   `amount` (number): Amount to be paid against the invoice. (Example: `100`)
    *   `meta` (object): Meta data to be recorded with the transaction
    *   `isPartialPayment` (boolean): Indicates if the order is intended to be a partial payment.

### 8. AUTHENTICATION:

*   **Scope(s):** `payments/orders.collectPayment`
*   **Auth Method(s):** `OAuth Access Token`, `Private Integration Token`
*   **Token Type(s):** `Sub-Account Token`
*   **Scheme:** `bearer`
*   **Bearer Format:** `JWT`
*   **In:** `header`
*   **Description:** Use the Access Token generated with user type as Sub-Account (OR) Private Integration Token of Sub-Account.

### 9. RESPONSE FORMAT:

*   **Status Code:** 200 OK
*   **Content Type:** `application/json`
*   **Schema:**
    ```json
    {
      "success": true
    }
    ```
*   **Description:** Indicates that the payment was successfully recorded.

### 10. PURPOSE:
This API allows recording a payment for a specific order, which updates the order status to "Paid".
