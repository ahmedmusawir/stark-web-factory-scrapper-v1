Here's a structured summary of the API documentation for "List schedules":

### 1. ENDPOINT NAME
List schedules

### 2. CATEGORY
Invoice Schedules

### 3. HTTP METHOD
GET

### 4. ENDPOINT URL
`/invoices/schedule`

### 5. FULL URL
`https://services.leadconnectorhq.com/invoices/schedule`

### 6. REQUIRED PARAMETERS

*   **Header Parameters:**
    *   `Version` (string): API Version. Possible values: [`2021-07-28`]
*   **Query Parameters:**
    *   `altId` (string): location Id / company Id based on altType. Example: `6578278e879ad2646715ba9c`
    *   `altType` (string): Alt Type. Possible values: [`location`]. Example: `location`
    *   `limit` (string): Limit the number of items to return. Example: `10`
    *   `offset` (string): Number of items to skip. Example: `10`

### 7. OPTIONAL PARAMETERS

*   **Query Parameters:**
    *   `status` (string): status to be filtered
    *   `startAt` (string): startAt in YYYY-MM-DD format. Example: `2023-01-01`
    *   `endAt` (string): endAt in YYYY-MM-DD format. Example: `2023-01-01`
    *   `search` (string): To search for an invoice by id / name / email / phoneNo. Example: `Alex`
    *   `paymentMode` (string): payment mode. Possible values: [`default`, `live`, `test`]. Example: `live`

### 8. AUTHENTICATION

*   **Scope(s)**: `invoices/schedule.readonly`
*   **Auth Method(s)**: `OAuth Access Token`, `Private Integration Token`
*   **Token Type(s)**: `Sub-Account Token`, `Agency Token`
*   **Scheme**: Bearer (JWT) in header, named `Authorization`.

### 9. RESPONSE FORMAT

*   **Status Code**: `200` (Successful response)
*   **Content Type**: `application/json`
*   **Schema**: An object containing:
    *   `schedules` (array of objects, required): A list of invoice schedule objects. Each object includes:
        *   `_id` (string): Schedule ID.
        *   `status` (string): Schedule Status (e.g., `draft`).
        *   `liveMode` (boolean): Indicates live mode.
        *   `altId` (string): Location Id or Agency Id.
        *   `altType` (string): Type of altId (e.g., `location`).
        *   `name` (string): Name of the invoice.
        *   `schedule` (object): Details about the schedule, including `executeAt` (string) and `rrule` (object with properties like `intervalType`, `interval`, `startDate`, `startTime`, `endDate`, `endTime`, `dayOfMonth`, `dayOfWeek`, `numOfWeek`, `monthOfYear`, `count`, `daysBefore`, `useStartAsPrimaryUserAccepted`, `endType`).
        *   `invoices` (array of objects): A list of associated invoice objects, each with comprehensive details (ID, status, amount paid, business details, currency, contact details, issue/due dates, discount, items, total, title, amount due, timestamps, automatic tax info, payment schedule).
        *   `businessDetails` (object): Business information associated with the schedule.
        *   `currency` (string): Currency used (e.g., `USD`).
        *   `contactDetails` (object): Contact information associated with the schedule.
        *   `discount` (object): Discount details.
        *   `items` (array of strings): Invoice items.
        *   `total` (number): Total amount.
        *   `title` (string): Title of the invoice.
        *   `termsNotes` (string): Terms notes.
        *   `compiledTermsNotes` (string): Compiled terms notes.
        *   `createdAt` (string): Creation timestamp.
        *   `updatedAt` (string): Last update timestamp.
    *   `total` (number, required): Total number of schedules returned.

### 10. PURPOSE
This API endpoint retrieves a list of invoice schedules based on provided filters and pagination parameters.
