Here is a structured summary of the API documentation for "Cancel a scheduled message.":

### STRUCTURED SUMMARY

1.  **ENDPOINT NAME:** Cancel a scheduled message.

2.  **CATEGORY:** Conversations (specifically Messages)

3.  **HTTP METHOD:** DELETE

4.  **ENDPOINT URL:** `/conversations/messages/:messageId/schedule`

5.  **FULL URL:** `https://services.leadconnectorhq.com/conversations/messages/:messageId/schedule`

6.  **REQUIRED PARAMETERS:**
    *   `Version` (string): API Version. Possible value: `2021-04-15` (in Header)
    *   `messageId` (string): Message Id. Example: `ve9EPM428h8vShlRW1KT` (in Path)

7.  **OPTIONAL PARAMETERS:**
    *   Not specified in documentation

8.  **AUTHENTICATION:**
    *   **Scope(s):** `conversations/message.write`
    *   **Auth Method(s):** `OAuth Access Token`, `Private Integration Token`
    *   **Token Type(s):** `Sub-Account Token`
    *   **Scheme:** Bearer (JWT)
    *   **Header:** `Authorization: Bearer <TOKEN>`

9.  **RESPONSE FORMAT:**
    *   **200 OK (Successful Cancellation):**
        *   Message: "The scheduled message was cancelled successfully"
        *   *Note: No specific JSON response body is provided for a 200 OK success in the documentation. An example response with `status: 404` and `message: "Failed cancel the scheduled message"` is erroneously listed under the 200 section.*
    *   **400 Bad Request:**
        ```json
        {
            "statusCode": 400,
            "message": "Bad Request"
        }
        ```
    *   **401 Unauthorized:**
        ```json
        {
            "statusCode": 401,
            "message": "Invalid token: access token is invalid",
            "error": "Unauthorized"
        }
        ```

10. **PURPOSE:** This endpoint allows users to cancel a previously scheduled message by providing its unique message identifier.
