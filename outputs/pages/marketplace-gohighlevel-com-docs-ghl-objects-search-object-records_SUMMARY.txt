Here is the structured summary of the API documentation for "Search Object Records":

### 1. ENDPOINT NAME:
Search Object Records

### 2. CATEGORY:
Objects

### 3. HTTP METHOD:
POST

### 4. ENDPOINT URL:
`/objects/:schemaKey/records/search`

### 5. FULL URL:
`https://services.leadconnectorhq.com/objects/:schemaKey/records/search`

### 6. REQUIRED PARAMETERS:
*   **Header Parameters:**
    *   `Version` (string): API Version. Possible values: `2021-07-28`
*   **Path Parameters:**
    *   `schemaKey` (string): custom object key. Example: `632c34b4c9b7da3358ac9891`
*   **Body Parameters (application/json):**
    *   `locationId` (string): Location Id. Example: `ve9EPM428h8vShlRW1KT`
    *   `page` (number): Page. Example: `1`
    *   `pageLimit` (number): Page Limit. Example: `10`
    *   `query` (string): Pass this query parameter to search using your searchable properties. For example, if you have a custom object called “Pets” and have configured “name” as a searchable property, you can pass `name:Buddy` to search for pets with the name “Buddy.” Example: `Buddy`
    *   `searchAfter` (string[]): Pagination cursor for subsequent requests. Example: `["sx6wyHhbFdRXh302Lunr","sx6wyHhbFdRXh302Lunr"]`

### 7. OPTIONAL PARAMETERS:
Not specified in documentation

### 8. AUTHENTICATION:
*   **Scope(s)**: `objects/record.readonly`
*   **Auth Method(s)**: `OAuth Access Token`, `Private Integration Token`
*   **Token Type(s)**: `Sub-Account Token`
*   **Scheme**: `bearer`
*   **Bearer Format**: `JWT`
*   **In**: `header`
*   **Description**: Use the Access Token generated with user type as Sub-Account (OR) Private Integration Token of Sub-Account.

### 9. RESPONSE FORMAT:

**200 OK (application/json)**
*   **Schema:**
    *   `records` (object[]): Array of record objects
        *   `id` (string): id of the record.
        *   `owner` (string[]): Owner (User's id). Limited to 1 for now. Only supported for custom objects for now.
        *   `followers` (string[]): Follower (User's ids). Limited to 10 and supported for custom objects for now.
        *   `properties` (string): Properties of the record (JSON string).
        *   `createdAt` (date-time): Date and time when the object was added.
        *   `updatedAt` (date-time): Date and time when the object was last updated.
        *   `locationId` (string): Location Id.
        *   `objectId` (string): ObjectId Id.
        *   `objectKey` (string): ObjectId key.
        *   `createdBy` (object): Created By Meta
            *   `channel` (string): Creation Channel.
            *   `createdAt` (string): Created At.
            *   `source` (string): From where the record was created.
            *   `sourceId` (string): User/Resource Id.
        *   `lastUpdatedBy` (object): Last Updated By Meta
            *   `channel` (string): Creation Channel.
            *   `createdAt` (string): Created At.
            *   `source` (string): From where the record was created.
            *   `sourceId` (string): User/Resource Id.
        *   `searchAfter` (number[]): Used for pagination.
    *   `total` (number): Total Number of records.

**400 Bad Request (application/json)**
*   **Schema:** `statusCode` (number), `message` (string)
*   **Example:** `{"statusCode":400,"message":"Bad Request"}`

**401 Unauthorized (application/json)**
*   **Schema:** `statusCode` (number), `message` (string), `error` (string)

### 10. PURPOSE:
This endpoint allows users to search for records within custom or standard objects (such as "business") by providing a query based on configured searchable properties.
