Here's a structured summary of the API documentation:

### 1. ENDPOINT NAME:
Create Calendar Resource

### 2. CATEGORY:
Calendars / Calendar Resources: Rooms & Equipments

### 3. HTTP METHOD:
POST

### 4. ENDPOINT URL:
`/calendars/resources/:resourceType`

### 5. FULL URL:
`https://services.leadconnectorhq.com/calendars/resources/:resourceType`

### 6. REQUIRED PARAMETERS:

*   **Header Parameters:**
    *   `Version` (string): API Version. Possible values: [`2021-04-15`]

*   **Path Parameters:**
    *   `resourceType` (string): Calendar Resource Type. Possible values: [`equipments`, `rooms`]

*   **Body Parameters:**
    *   `locationId` (string): Location ID
    *   `name` (string): Name of the resource
    *   `description` (string): Description of the resource
    *   `quantity` (number): Quantity of the equipment.
    *   `outOfService` (number): Quantity of the out of service equipment.
    *   `capacity` (number): Capacity of the room.
    *   `calendarIds` (string[]): Service calendar IDs to be mapped with the resource. Possible values: `<= 100`.

### 7. OPTIONAL PARAMETERS:
Not specified in documentation (all listed body parameters are marked as `required` in the request section).

### 8. AUTHENTICATION:

*   **Scope(s)**: `calendars/resources.write`
*   **Auth Method(s)**: `OAuth Access Token`, `Private Integration Token`
*   **Token Type(s)**: `Sub-Account Token`
*   **Scheme**: `bearer`
*   **Bearer Format**: `JWT`
*   **In**: `header`
*   **Description**: Use the Access Token generated with user type as Sub-Account (OR) Private Integration Token of Sub-Account.

### 9. RESPONSE FORMAT:

*   **201 Created (Success)**
    *   **Structure (application/json):**
        *   `locationId` (string): Location ID of the resource
        *   `name` (string): Name of the resource (Example: `yoga room`)
        *   `resourceType` (string): Possible values: [`equipments`, `rooms`]
        *   `isActive` (boolean): Whether the resource is active
        *   `description` (string): Description of the resource
        *   `quantity` (number): Quantity of the resource
        *   `outOfService` (number): Indicates if the resource is out of service (Example: `0`)
        *   `capacity` (number): Capacity of the resource (Example: `85`)
        *   `calendarIds` (string[]): Calendar IDs (Example: `["Jsj0xnlDDjw0SuvX1J13","oCM5feFC86FAAbcO7lJK"]`)
    *   **Example:**
        ```json
        {"locationId":"string","name":"yoga room","resourceType":"equipments","isActive":true,"description":"string","quantity":0,"outOfService":0,"capacity":85,"calendarIds":["Jsj0xnlDDjw0SuvX1J13","oCM5feFC86FAAbcO7lJK"]}
        ```

*   **400 Bad Request (Error)**
    *   **Structure (application/json):**
        *   `statusCode` (number)
        *   `message` (string)
    *   **Example:**
        ```json
        {"statusCode":400,"message":"Bad Request"}
        ```

*   **401 Unauthorized (Error)**
    *   **Structure (application/json):**
        *   `statusCode` (number)
        *   `message` (string)
        *   `error` (string)
    *   **Example:**
        ```json
        {"statusCode":401,"message":"Invalid token: access token is invalid","error":"Unauthorized"}
        ```

### 10. PURPOSE:
This endpoint allows you to create a new calendar resource (either an equipment or a room) by specifying its type, location, name, description, quantity/capacity, and associated calendar IDs.
