Here's a structured summary of the `OutboundMessage` API documentation:

### 1. ENDPOINT NAME
OutboundMessage

### 2. CATEGORY
Webhook

### 3. HTTP METHOD
Not applicable (This documentation describes a webhook payload sent by HighLevel, not an API endpoint to be called.)

### 4. ENDPOINT URL
Not applicable (This documentation describes a webhook payload sent by HighLevel. The URL to which this payload is sent is configured by the user in the HighLevel system.)

### 5. FULL URL
Not applicable (The documentation URL is: `https://marketplace.gohighlevel.com/docs/webhook/OutboundMessage/index.html`)

### 6. PAYLOAD FIELDS (Parameters of the webhook payload)
*   **type** (string): The type of the webhook event. Always "OutboundMessage".
*   **locationId** (string): The unique identifier for the location (sub-account) where the message originated.
*   **attachments** (array of strings): An array of URLs to any attachments (e.g., call recording URL, voicemail URL).
*   **body** (string): The content of the message. For emails, this can contain HTML.
*   **contactId** (string): The unique identifier for the contact to whom the message was sent.
*   **contentType** (string): The content type of the message (e.g., "text/plain"). (Found in general message example)
*   **conversationId** (string): The unique identifier for the conversation.
*   **dateAdded** (string): The date and time (ISO 8601 format) when the message was added.
*   **direction** (string): The direction of the message. Typically "outbound" for this webhook, but example shows "inbound".
*   **messageType** (string): The type of message sent. Possible values include "SMS", "CALL", "VoiceMail", "Email", "GMB", "FB", "IG", "Live Chat".
*   **status** (string): The delivery status of the message (e.g., "delivered", "completed").
*   **messageId** (string): A unique identifier for the specific message.
*   **userId** (string): The unique identifier for the user who sent the message or initiated the call.
*   **source** (string): The source application or channel from which the message was sent (e.g., "app").
*   **conversationProviderId** (string): The unique identifier for the conversation provider.
*   **callDuration** (number): The length of the call in seconds. (Specific to `messageType: "CALL"`)
*   **callStatus** (string): The status of the call. Possible values include "completed", "voicemail". (Specific to `messageType: "CALL"`)
*   **chatWidgetId** (string): The unique identifier of the chat widget. (Found in general message example, specific to Live Chat/SMS)
*   **emailMessageId** (string): A unique identifier for the email message. (Specific to `messageType: "Email"`)
*   **threadId** (string): The unique identifier for the email thread. (Specific to `messageType: "Email"`)
*   **provider** (string): The email service provider. (Specific to `messageType: "Email"`)
*   **to** (array of strings): The recipient email addresses. (Specific to `messageType: "Email"`, example shows array, schema shows string)
*   **cc** (string): Carbon copy recipient email addresses. (Specific to `messageType: "Email"`, from schema)
*   **bcc** (string): Blind carbon copy recipient email addresses. (Specific to `messageType: "Email"`, from schema)
*   **from** (string): The sender's email address and display name (e.g., "Internal Notify <sample@email.service>"). (Specific to `messageType: "Email"`, from example)
*   **subject** (string): The subject line of the email. (Specific to `messageType: "Email"`, from example)

### 7. OPTIONAL PARAMETERS
Not explicitly differentiated as optional in the documentation's schemas. All fields listed above are part of the potential payload. Some fields are conditional based on the `messageType`.

### 8. AUTHENTICATION
Not specified in documentation for receiving the webhook. Typically, webhook integrations involve a signing secret for payload verification, but this document does not detail such a mechanism for the `OutboundMessage` webhook.

### 9. RESPONSE FORMAT
This documentation describes the *payload format* that HighLevel sends to a configured webhook URL. It does not describe an API response from HighLevel, nor does it specify what response HighLevel expects from the receiving server (though typically a 200 OK status code is expected).

### 10. PURPOSE
This webhook is called whenever a user sends a message to a contact, providing details about the outbound communication, including SMS, calls, voicemails, and emails.

### 11. TAGS
Webhook Events, Outbound Message, Messaging, Communication, Notification, Call, SMS, Email, Voicemail, Live Chat, GMB, FB, IG.

### Code Examples
JSON examples for Message, Call and Voicemail, Voicemail send through workflow, and Email are provided in the documentation.
