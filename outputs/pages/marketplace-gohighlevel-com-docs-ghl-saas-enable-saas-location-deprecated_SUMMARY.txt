Here is a structured summary of the provided API documentation:

### 1. ENDPOINT NAME:
Enable SaaS for Sub-Account (Formerly Location)

### 2. CATEGORY:
Saas

### 3. HTTP METHOD:
POST

### 4. ENDPOINT URL:
`/saas-api/public-api/enable-saas/:locationId`

### 5. FULL URL:
`https://services.leadconnectorhq.com/saas-api/public-api/enable-saas/:locationId`

### 6. REQUIRED PARAMETERS:

*   **Header Parameters:**
    *   `Version` (string): API Version. Possible values: `2021-04-15`.
*   **Path Parameters:**
    *   `locationId` (string): Location ID to enable SaaS for. Example: `AUKAtFVo0lWezBsBQ3FE`.
*   **Body Parameters (application/json):**
    *   `companyId` (string): No description provided.
    *   `isSaaSV2` (boolean): Denotes if it is a saas v2 or v1 sub-account. Example: `true`.

### 7. OPTIONAL PARAMETERS:

*   **Body Parameters (application/json):**
    *   `stripeAccountId` (string): Stripe account id (Required only for SaaS V1). Example: `acct_1QDPY5FpU9DlKp7RQ8BXfywx`.
    *   `name` (string): Name of the stripe customer (Required only for SaaS V1). Example: `John Doe`.
    *   `email` (string): Email of the stripe customer (Required only for SaaS V1). Example: `john.doe@example.com`.
    *   `stripeCustomerId` (string): Stripe customer id if exists (Required only for SaaS V1). Example: `cus_1QDPY5FpU9DlKp7RQ8BXfywx`.
    *   `contactId` (string): Agency subaccount used for payment provider integration (Required Only for SaaS V2). Example: `1QDPY5FpU9DlKp7RQ8BXfywx`.
    *   `providerLocationId` (string): Agency Subaccount ID. Example: `r06mdj4OrrERzYDvsOdh`.
    *   `description` (string): Description. Example: `Description`.
    *   `saasPlanId` (string): Required only while pre-configuring saas subscription. Example: `1QDPY5FpU9DlKp7RQ8BXfywx`.
    *   `priceId` (string): Required only while pre-configuring saas subscription. Example: `price_1QDPY5FpU9DlKp7RQ8BXfywx`.

### 8. AUTHENTICATION:

*   **Auth Method(s):** `OAuth Access Token`, `Private Integration Token`
*   **Token Type(s):** `Agency Token`
*   **Scheme:** Bearer (JWT)
*   **In:** Header (`Authorization` header)
*   **Description:** Use the Access Token generated with user type as Company.

### 9. RESPONSE FORMAT:

*   **Success (200 OK):**
    *   **Description:** SaaS enabled successfully for location.
    *   **Content Type:** `application/json`
    *   **Schema:**
        ```json
        {
          "data": {
            "customer_id": "cus_1QDPY5FpU9DlKp7RQ8BXfywx",
            "ok": true,
            "paymentMethodAdded": true
          }
        }
        ```
*   **Error Responses:**
    *   **400 Bad Request:**
        ```json
        {"statusCode":400,"message":"Bad Request"}
        ```
    *   **401 Unauthorized:**
        ```json
        {"statusCode":401,"message":"Invalid token: access token is invalid","error":"Unauthorized"}
        ```
    *   **404 Resource Not Found:**
        ```json
        {"statusCode":404,"message":["Contact not found","User not found","Group not found","Channel not found"]}
        ```
    *   **500 Internal Server Error:**
        ```json
        {"statusCode":500,"message":"Internal Server Error"}
        ```

### 10. PURPOSE:
This endpoint enables SaaS functionality for a specific sub-account (formerly known as location) based on the provided data, supporting both SaaS V1 and SaaS V2 configurations. This endpoint is deprecated.
