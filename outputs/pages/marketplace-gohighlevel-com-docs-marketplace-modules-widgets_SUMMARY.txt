## Structured Summary: Web Widgets Integration Guide

### 1. ENDPOINT NAME:
Web Widgets (Integration Guide for Funnel Builder)

### 2. CATEGORY:
Marketplace Modules

### 3. HTTP METHOD:
Not applicable. This documentation describes how to develop and integrate client-side web widgets within the HighLevel funnel builder using iFrame communication and browser events, not a traditional REST API endpoint.

### 4. ENDPOINT URL:
Not applicable. Communication occurs via JavaScript mechanisms like `postmate` for iFrame messaging and `window.dispatchEvent` for browser events.

### 5. FULL URL:
Not applicable.

### 6. REQUIRED PARAMETERS:

#### For Widget Application Emitting Code to Funnel Builder (via `parent?.emit('code', ...)`):
*   `html` (string): HTML content required for the widget to render along with its styles.
    *   **Example Structure:** `<style>{Your styles goes here}</style><div class="hl-banner">{YourHTML content goes here}</div>`
*   `elementStore` (Object): An object containing all variables that represent the current settings of the widget. Variable names and structure are developer-defined (e.g., `{widgetHeight: number, widgetWidth: number, image: string}`).

#### For Widget Application Receiving Initial State from Funnel Builder (on handshake/initialization):
*   `elementStore` (Object): An object representing the previously saved settings of the widget by the user in the funnel builder. This should be used to prefill the widget's settings on revisits.

### 7. OPTIONAL PARAMETERS:

#### For Widget Application Emitting Code to Funnel Builder (via `parent?.emit('code', ...)`):
*   `js` (string): JavaScript code required for the widget to run in the website. This code should not be wrapped inside `<script />` tags.

### 8. AUTHENTICATION:
*   **Method:** Developer account registration on the HighLevel App Marketplace is required to create and upload widgets.
*   **Scopes/Token Types:** Not explicitly specified for the runtime communication of the widget itself, but platform authentication is necessary for app creation and submission.

### 9. RESPONSE FORMAT:
Not applicable in the traditional HTTP sense. Communication between the widget's iFrame application and the funnel builder happens asynchronously through event emission and receipt:
*   The widget application emits a `code` payload to the parent containing `html`, `js`, and `elementStore`.
*   The widget application receives an `elementStore` object from the parent upon initialization/handshake.
*   The widget application can dispatch browser events (`customWidgetOpenPopup`, `customWidgetGoToNextStep`) to trigger actions in the funnel preview.

### 10. PURPOSE:
This documentation guides developers on how to create, set up, and integrate custom web widgets into the HighLevel funnel builder, enabling dynamic rendering and seamless communication between the widget application (hosted in an iFrame) and the builder environment.

### Additional Notes:

*   **Communication Mechanism:** Uses `postmate` for iFrame communication between the custom widget application and the funnel builder.
*   **Triggerable Events from Widget (via `window.dispatchEvent`):**
    *   `customWidgetOpenPopup`: Triggers an action to open a popup on the funnel preview side.
    *   `customWidgetGoToNextStep`: Triggers an action to move to the next step/page in the funnel/website (Note: documentation has a typo `customWidgetGoToNextStGoToNextStep`).
*   **Upload Format:** `.zip` file containing the built HTML, CSS, and JS files (or the `build/dist` folder for framework-based projects). `.RAR` files are not supported.
*   **Paths:** Relative paths should be used for assets within the widget project.
*   **Frameworks:** Supports JS frameworks like Angular, React, Vue.
*   **Developer Resources:**

*   **Code Examples:** JavaScript code examples for `emit` and `dispatchEvent` are provided within the documentation.
