Here's a structured summary of the API documentation for "Update Appointment":

### 1. ENDPOINT NAME:
Update Appointment

### 2. CATEGORY:
Calendars

### 3. HTTP METHOD:
PUT

### 4. ENDPOINT URL:
`/calendars/events/appointments/:eventId`

### 5. FULL URL:
`https://services.leadconnectorhq.com/calendars/events/appointments/:eventId`

### 6. REQUIRED PARAMETERS:
*   **Header Parameters:**
    *   `Version` (string): API Version. Possible values: [`2021-04-15`]
*   **Path Parameters:**
    *   `eventId` (string): Event Id or Instance id. For recurring appointments send masterEventId to modify original series. Example: `ocQHyuzHvysMo5N5VsXc`, `ocQHyuzHvysMo5N5VsXc_1729821600000_1800`

### 7. OPTIONAL PARAMETERS:
*   **Body Parameters:**
    *   `title` (string): Title. Example: `Test Event`
    *   `meetingLocationType` (string): Meeting location type. If `address` is provided, defaults to `custom`. Possible values: [`custom`, `zoom`, `gmeet`, `phone`, `address`, `ms_teams`, `google`]. Example: `custom`
    *   `meetingLocationId` (string): The unique identifier for the meeting location. Default value: `default`. Example: `custom_0`
    *   `overrideLocationConfig` (boolean): Flag to override location config. `false` if only `meetingLocationId` is provided, `true` if only `meetingLocationType` is provided. Example: `true`
    *   `appointmentStatus` (string): Possible values: [`new`, `confirmed`, `cancelled`, `showed`, `noshow`, `invalid`]. Example: `confirmed`
    *   `assignedUserId` (string): Assigned User Id. Example: `0007BWpSzSwfiuSl0tR2`
    *   `description` (string): Appointment Description. Example: `Booking a call to discuss the project`
    *   `address` (string): Appointment Address. Example: `Zoom`
    *   `ignoreDateRange` (boolean): If set to true, the minimum scheduling notice and date range would be ignored. Example: `false`
    *   `toNotify` (boolean): If set to false, the automations will not run. Example: `false`
    *   `ignoreFreeSlotValidation` (boolean): If true the time slot validation would be avoided for any appointment creation (even the ignoreDateRange). Example: `true`
    *   `rrule` (string): RRULE as per the iCalendar (RFC 5545) specification for recurring events.
    *   `calendarId` (string): Calendar Id. Example: `CVokAlI8fgw4WYWoCtQz`
    *   `startTime` (string): Start Time. Example: `2021-06-23T03:30:00+05:30`
    *   `endTime` (string): End Time. Example: `2021-06-23T04:30:00+05:30`

### 8. AUTHENTICATION:
*   **Scope(s):** `calendars/events.write`
*   **Auth Method(s):** `OAuth Access Token`, `Private Integration Token`
*   **Token Type(s):** `Sub-Account Token`
*   **Scheme:** `bearer` (bearerFormat: `JWT`)
*   **In:** `header` (as `Authorization: Bearer <TOKEN>`)

### 9. RESPONSE FORMAT:

**200 Successful response**
*   **Content-Type:** `application/json`
*   **Schema:**
    *   `calendarId` (string, required): Calendar Id. Example: `CVokAlI8fgw4WYWoCtQz`
    *   `locationId` (string, required): Location Id. Example: `C2QujeCh8ZnC7al2InWR`
    *   `contactId` (string, required): Contact Id. Example: `0007BWpSzSwfiuSl0tR2`
    *   `startTime` (string): Start Time. Example: `2021-06-23T03:30:00+05:30`
    *   `endTime` (string): End Time. Example: `2021-06-23T04:30:00+05:30`
    *   `title` (string): Title. Example: `Test Event`
    *   `meetingLocationType` (string): Meeting Location Type. Default value: `default`. Example: `custom`
    *   `appointmentStatus` (string): Possible values: [`new`, `confirmed`, `cancelled`, `showed`, `noshow`, `invalid`, `active`, `completed`]. Example: `confirmed`
    *   `assignedUserId` (string): Assigned User Id. Example: `0007BWpSzSwfiuSl0tR2`
    *   `address` (string): Appointment Address. Example: `Zoom`
    *   `isRecurring` (boolean): true if the event is recurring otherwise false. Example: `true`
    *   `rrule` (string): RRULE as per the iCalendar (RFC 5545) specification for recurring events.
    *   `id` (string, required): Id. Example: `0TkCdp9PfvLeWKYRRvIz`

**400 Bad Request**
*   **Content-Type:** `application/json`
*   **Schema:** `statusCode` (number), `message` (string)
*   **Example:** `{"statusCode":400,"message":"Bad Request"}`

**401 Unauthorized**
*   **Content-Type:** `application/json`
*   **Schema:** `statusCode` (number), `message` (string), `error` (string)
*   **Example:** `{"statusCode":401,"message":"Invalid token: access token is invalid","error":"Unauthorized"}`

### 10. PURPOSE:
This endpoint allows for updating the details of an existing appointment or a series of recurring appointments within the calendar system.
