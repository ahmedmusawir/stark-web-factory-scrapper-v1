Here is a structured summary of the provided API documentation for the "Conversation Provider - Outbound Message" webhook:

### 1. ENDPOINT NAME
Conversation Provider - Outbound Message

### 2. CATEGORY
Webhook / Conversations

### 3. HTTP METHOD
Not applicable. This documentation describes the payload sent *by* HighLevel *to* a custom provider (webhook receiver), not an API call made *to* HighLevel.

### 4. ENDPOINT URL
Not applicable. The URL for receiving this webhook is configured by the user within HighLevel for their custom webhook provider.

### 5. FULL URL
Not applicable.

### 6. REQUIRED PARAMETERS (Present in all webhook payloads for this event)
*   **contactId** (string): The ID of the contact to whom the message is sent.
*   **locationId** (string): The ID of the location (sub-account) from which the message originates.
*   **messageId** (string): The unique ID of the message.
*   **type** (string - "Email" / "SMS"): Indicates the type of message being sent.
*   **attachments** (array): An array of URLs for any attachments included with the message.
*   **userId** (string): The ID of the user who sent the message.

### 7. OPTIONAL PARAMETERS (Conditionally present based on `type`)
These parameters are present in the payload based on the `type` field:

*   **For `type: "SMS"`:**
    *   **message** (string): The text content of the SMS message.
    *   **phone** (string): The phone number to which the SMS message is sent.

*   **For `type: "Email"`:**
    *   **emailMessageId** (string): The unique ID of the email message.
    *   **emailTo** (string): The recipient's email address.
    *   **emailFrom** (string): The sender's email address, often including a name (e.g., "From Name <email@gmail.com>").
    *   **html** (string): The HTML content of the email message.
    *   **subject** (string): The subject line of the email.

### 8. AUTHENTICATION
Not specified in documentation. (Authentication for receiving the webhook, such as signature verification, would typically be configured by the custom provider).

### 9. RESPONSE FORMAT
Not applicable. This documentation describes the structure of the JSON payload sent by HighLevel to a custom webhook receiver. A successful response from the webhook receiver to HighLevel would typically be an HTTP 2xx status code (e.g., 200 OK).

### 10. PURPOSE
This webhook is called whenever a user sends a message (SMS or Email) to a contact and has a custom provider set as the default channel in their HighLevel settings.

### 11. TAGS
Webhook Events, Conversation, Outbound Message, SMS, Email, Provider

### 12. CODE EXAMPLES
Only JSON payload examples for SMS and Email are provided. No code examples (Python, Node, cURL) for sending or receiving the webhook are present.
