### 1. ENDPOINT NAME:
InboundMessage

### 2. CATEGORY:
Webhook

### 3. HTTP METHOD:
Not directly specified, but webhooks are typically sent via `POST` requests from HighLevel to the configured listener URL.

### 4. ENDPOINT URL:
This documentation describes a webhook event payload sent *by* HighLevel, not an API endpoint *to call*. Therefore, there is no specific "Endpoint URL" for integrators to call for this event. Integrators configure their own listener endpoint to receive this webhook.

### 5. FULL URL:
Not applicable as this describes a webhook event sent *by* HighLevel to a configurable listener URL.

### 6. REQUIRED PARAMETERS (Payload Fields):
These fields are expected to be present in all InboundMessage webhook payloads, regardless of `messageType`.
-   `type` (string): The type of the event, always "InboundMessage".
-   `locationId` (string): The unique identifier for the sub-account (formerly location) where the message was received.
-   `attachments` (array): An array of attachment URLs. Can be empty if no attachments are present.
-   `body` (string): The content of the message. Can be an empty string for certain message types (e.g., calls without transcripts, but voicemails typically have an attachment URL).
-   `contactId` (string): The unique identifier for the contact who sent the message.
-   `conversationId` (string): The unique identifier for the conversation this message belongs to.
-   `dateAdded` (string): The UTC timestamp (ISO 8601 format) when the message was received by HighLevel.
-   `direction` (string): The direction of the message, always "inbound" for this webhook.
-   `messageType` (string): The channel type through which the message was received (e.g., "SMS", "CALL", "Email", "GMB", "FB", "IG", "Live Chat").
-   `conversationProviderId` (string): The unique identifier for the conversation provider.

### 7. OPTIONAL PARAMETERS (Conditional Payload Fields):
These fields are part of the webhook payload but may only be present or relevant for specific `messageType` values.
-   `contentType` (string): The content type of the message (e.g., "text/plain"). (Primarily for text-based messages like SMS)
-   `status` (string): The delivery or processing status of the message (e.g., "delivered", "completed", "voicemail").
-   `messageId` (string): The unique identifier for the specific message.
-   `userId` (string): The unique identifier for the user associated with the conversation (e.g., the user who received/answered a call).
-   `callDuration` (number): The duration of the call in seconds. (Present when `messageType` is "CALL")
-   `callStatus` (string): The status of the call (e.g., "completed" if answered, "voicemail" if it went to voicemail). (Present when `messageType` is "CALL")
-   `chatWidgetId` (string): The unique identifier of the chat widget. (Present when `messageType` is "Live Chat")
-   `emailMessageId` (string): The unique identifier for the email message. (Present when `messageType` is "Email")
-   `threadId` (string): The unique identifier for the email thread. (Present when `messageType` is "Email")
-   `provider` (string): The email service provider. (Present when `messageType` is "Email")
-   `to` (array of string): An array of recipient email addresses. (Present when `messageType` is "Email")
-   `cc` (string): The CC email address. (Present when `messageType` is "Email")
-   `bcc` (string): The BCC email address. (Present when `messageType` is "Email")
-   `from` (string): The sender's email address. (Observed in Email example, expected for `messageType` is "Email")
-   `subject` (string): The subject line of the email. (Observed in Email example, expected for `messageType` is "Email")

### 8. AUTHENTICATION:
Not specified in the documentation for this specific webhook event. HighLevel webhooks typically rely on configuring a trusted URL or optionally a shared secret for payload verification, but no explicit details for authentication are provided here.

### 9. RESPONSE FORMAT:
The webhook listener (integrator's server) is expected to return a 2xx HTTP status code (e.g., 200 OK) to acknowledge successful receipt of the event. The content of this response is not specified by HighLevel as it's primarily an acknowledgment to prevent retries.

### 10. PURPOSE:
This webhook is called whenever a contact sends a message to the user through various channels (Call, Voicemail, SMS, GMB, FB, IG, Email, Live Chat).

### 11. TAGS:
Webhook Events, Inbound Message, Contact Message, Call, Voicemail, SMS, GMB, FB, IG, Email, Live Chat, Conversation.

JSON examples of the webhook payload for different message types (Message, Call, Email) are provided in the documentation. No code examples in Python, Node, cURL, or other programming languages are present.
