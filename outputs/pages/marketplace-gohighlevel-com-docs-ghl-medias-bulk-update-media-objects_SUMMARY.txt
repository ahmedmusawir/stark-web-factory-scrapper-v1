Here is a structured summary of the API documentation:

### 1. ENDPOINT NAME:
Bulk Update Files/ Folders

### 2. CATEGORY:
Media Storage (under Medias)

### 3. HTTP METHOD:
PUT

### 4. ENDPOINT URL:
`/medias/update-files`

### 5. FULL URL:
`https://services.leadconnectorhq.com/medias/update-files`

### 6. REQUIRED PARAMETERS:
*   **Version** (string, header): API Version.
    *   Possible values: [`2021-07-28`]
*   **altId** (string, body): Location identifier.
    *   Example: `sx6wyHhbFdRXh302LLNR`
*   **altType** (string, body): Type of entity that owns the files.
    *   Possible values: [`location`]
    *   Example: `location`
*   **filesToBeUpdated** (object[], body): Array of file objects to be updated.
    *   **id** (string, nested in filesToBeUpdated object): Unique identifier of the file or folder to be updated.
        *   Example: `686f9817f0d3165be9fbcef6`

### 7. OPTIONAL PARAMETERS:
*   **name** (string, nested in filesToBeUpdated object): New name for the file or folder.
    *   Example: `Updated File Name.pdf`

### 8. AUTHENTICATION:
*   **Auth Method(s)**: `OAuth Access Token`, `Private Integration Token`
*   **Token Type(s)**: `Sub-Account Token`
*   **Scheme**: Bearer (JWT)
*   **Description**: Use the Access Token generated with user type as Sub-Account (OR) Private Integration Token of Sub-Account.

### 9. RESPONSE FORMAT:
*   **Status Code**: `200` (Successful response)
*   **Content Type**: `application/json`
*   **Schema**:
    ```json
    [
      {
        "updated": true,
        "id": "686f9817f0d3165be9fbcef6"
      }
    ]
    ```

### 10. PURPOSE:
This endpoint updates metadata or status for multiple files and folders within the media storage.

Media Storage, Files, Folders, Bulk Update, Update, Metadata, Status, File Management
