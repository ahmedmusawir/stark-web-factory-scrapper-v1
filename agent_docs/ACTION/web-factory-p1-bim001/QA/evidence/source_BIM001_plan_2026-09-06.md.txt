66: ## B. Run-root constant; no mkdir at import
67: 
68: - **`RUN_ROOT = OUTPUT_DIR`** (module level, line ~42 area, next to `PAGE_DIR`/`SUMMARY_PATH`). Run folder = `RUN_ROOT / project / "runs" / run_id`. It equals `OUTPUT_DIR` in production so the layout is `outputs/<project>/runs/<run_id>/` (AC-10); tests redirect `crawler.RUN_ROOT = tmp_path` (AC-71a) so nothing lands in the real `outputs/`.
69: - The manifest's `run_dir` string (AC-32) is built from parts — `f"outputs/{project}/runs/{run_id}"` — not from the filesystem path, so it reads correctly even when `RUN_ROOT` is redirected in tests.
70: - **No `mkdir` at import.** Module level defines constants only (as today, `crawler.py:36-46`). `RunFolder.create()` does `run_dir.mkdir(parents=True)` + `(run_dir/"html").mkdir()` and is called from `main()` only. Every `mkdir` hit in `grep -n mkdir` will be inside a function body (AC-12). bim000 test 7 stays unchanged.

88: ## E. Collision suffix and URL → file mapping
89: 
90: - `RunFolder.allocate_slug(base)`: an in-run `dict[str, int]` counter. First use of `base` → `base`, counter 1. Each later use → counter += 1 → `f"{base}-{counter}"` (`slug-2.html`, `slug-3.html`, …). Never overwrites: the filename is decided before writing and each name is unique within the run (AC-23). Only captured pages allocate (a blocked page never consumes a suffix); non-captured pages record the plain base slug as `slug` (see §I-2).
91: - Mapping recorded in `manifest.json["pages"][i]`: `url`, `slug` (suffix included), `html_file = f"html/{slug}.html"`, `html_bytes`; and in `absences.json` for the rest (AC-35, AC-41). The stage log line also names the URL and outcome (AC-51).

134: 1. **AC-31 vs AC-92 — the token `playwright`.** AC-31 requires `manifest.playwright_version == "1.52.0"`. 135: 2. **AC-35 `md_file` under collision (R1 vs R4).** bim000's `save_markdown` writes `pages/<base-slug>.md` and overwrites on collision (R1: unchanged). The manifest `slug` carries the `-2` suffix (R4). AC-35 says `md_file` is `"pages/<slug>.md"` — with the suffixed slug that names a file that does not exist. I will record the file actually written (`pages/<base-slug>.md`), which is truthful; the literal check differs only for colliding URLs. The live smoke has no collisions, so this is unit-level only.
136: 3. **AC-11/AC-14 run_id granularity.** `run_id` is `started_at` to the second. Two runs starting in the same second would share a folder and violate AC-14. Mitigation: `RunFolder.create()` checks existence and, if the folder already exists, waits until the clock passes to the next second and recomputes `started_at`/`run_id` — keeps the regex and the "same instant as `started_at`" property. Cost ≤ 1 s, only in that case. Alternative would be a suffix, which breaks the AC-11 regex. Confirm the mitigation is acceptable.
137: 4. **AC-32 `command` reconstruction.** Under `python -m`, `sys.argv[0]` is the script path, not `python -m smart_crawler.crawler`. I will emit `"python -m smart_crawler.crawler " + " ".join(sys.argv[1:])` — the canonical invocation form the spec asks for, not the raw argv[0]. Values with spaces (e.g. an invalid project name) never reach the manifest because validation exits first. Flagging because it is a reconstruction, not a verbatim capture.
138: 5. **AC-74 assumption (INFERENCE, live only).** "Each captured file starts with `<!DOCTYPE` or `<html`" depends on crawl4ai's `result.html` being Playwright's `page.content()`, which normally begins with `<!DOCTYPE html>`. I cannot verify offline; if a page fails this, it is a P3 finding, not something bim001 code should paper over (byte-for-byte rule).
