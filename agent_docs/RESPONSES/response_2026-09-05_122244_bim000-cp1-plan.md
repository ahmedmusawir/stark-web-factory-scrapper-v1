**Behavior changes that DO reach our code (not breaking, but different):**
1. **Anti-bot detector in `arun()` (new since 0.6.3).** After every fetch, `is_blocked(status_code, html)` runs. HTTP 429 → blocked. HTTP 403/503 with HTML → blocked. Any status with tier-1 block-page markers (Akamai/Cloudflare/PerimeterX/DataDome/Incapsula/Sucuri/Kasada signatures) → blocked. Tier-2 generic terms ("Access Denied", `g-recaptcha`) only on pages <10 KB with error status. Tier-3 structural check on HTML <50 KB (no `<body>`, no content elements). **Blocked → `result.success=False`, `error_message="Blocked by anti-bot protection: …"`.** `async_webcrawler.py:55, 405, 512, 611-630`; `antibot_detector.py:191-281`. Effect on our unchanged `crawler.py`: its existing failure branch (`crawler.py:65-71`) now fires on 403/429 and prints the status and error — the soft-403 blind spot from run-002 is closed by the library itself. `max_retries` defaults to 0 → **no retries** (AC-06 "crawler otherwise unchanged" holds). INFERENCE: false-positive risk on cyberizegroup.com is low — tier-1 markers are vendor block-page signatures, tier-2 needs an error status, tier-3 needs <50 KB HTML (run-002 pages produced 6-29 KB of *markdown*, so HTML is well above that). The smoke is the proof.
