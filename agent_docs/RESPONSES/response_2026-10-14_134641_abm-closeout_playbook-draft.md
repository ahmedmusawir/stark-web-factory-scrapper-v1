# Reusable ABM playbook — DRAFT, worked Web Factory example

**Purpose:** take a bounded objective from scope through evidence, review, repair, handoff and an honest closeout. This is a local draft extracted from the Web Recon campaign, not an adopted Factory manual or an authorization to run commands. The broader factory-speed redesign stays parked.

**Evidence vocabulary:** *demonstrated* means a dated result exists; *local proof* does not imply live success; *accepted task* does not imply independent certification; *proposed* is not implemented or approved. Historical runs are not tests performed during this documentation pass.

## 1. Scope — agree what outcome is actually being built

**Demonstrated:** Tony's October 7 direction changed the active product to DECIDE → COLLECT → PREPARE, replacing the experimental controller-repair loop with explicit human selection and ordinary browser lifecycle. The original 48-AC/24-group packet remained preserved; it was not silently passed. [Current collector direction](../ACTION/wf-scrapper-abm/COLLECTOR_SIMPLIFICATION.md), lines 3–11.

Record objective, inputs, selected outputs, exclusions, owners, acceptance basis and the distinction between engineering demonstration and formal QA. Keep internal tasks subordinate to the whole outcome; no new approval gate is needed for each already-authorized routine step. An allocation ceiling is not permission to retry a stopped run.

**Worked example:** the original goal was Capture → Raw Recon Package → Prepare → Architect Data Pack. The demonstrated smaller flow produces a saved review, explicit collection and agent-prepared Markdown/brief/gaps. Those deliverables are useful, but do not certify the old full Data Pack/twins/QA contract. A closeout record must state which scope it covers. [Original ABM scope and exit](../ACTION/wf-scrapper-abm/ABM_BRIEF.md), lines 34–50.

**Proposed improvement:** use one short scope/supersession record naming the old obligations that remain pending and the current entry points. Approve it before claiming formal closure; never reconstruct a Director ruling after the fact.

## 2. Preparation — inspect the actual specimen before acting

**Demonstrated:** inspect branch/full HEAD/dirty and untracked work, current checkpoint, applicable instructions, installed APIs and saved evidence. Match the reviewed source inventory before a bounded run. Preserve prior attempts. HEAD alone cannot identify reviewed untracked/dirty code. [First human-selected three-page collection](response_2026-10-11_203505_first-selected-collection.md), lines 31–38; [Growth Call bounded follow-up](response_2026-10-13_223736_growth-call-follow-up.md), lines 33–38.

A factual readback/handoff should bind: files/dependencies, acceptance/checks, fixture facts, resource bounds, source bytes, commands, expected versus actual evidence and blockers. Label unproved mechanisms. Use existing installed tools; do not treat old recovery commands as new permission. If a tool/API boundary is uncertain, inspect local dependency source before guessing.

**Worked example:** the custom browser path needed native identity, redirect and cancellation proofs. The later simpler path deliberately stopped promising low-level per-resource/per-hop cancellation control. It bounds planned calls and saves per-result progress instead. These are different contracts, not interchangeable PASS evidence. [Current collector direction](../ACTION/wf-scrapper-abm/COLLECTOR_SIMPLIFICATION.md), lines 83–90.

**Proposed improvement:** maintain a compact governing-input index and exact file/hash inventory per candidate; keep source, contract and plan identities separate. A dependency lock already exists; a successful working venv is not proof of clean-install reproducibility. [Approved prospective 1.2 rulings](../ACTION/wf-scrapper-abm/ABM_RULINGS_1_2.md).

## 3. Execution — act continuously inside the authorized boundary

**Demonstrated practices:** explicit phase/mode, sequential planned calls, default five-second completion gap, no automatic retries/alternate client, first implemented access refusal/challenge stops later planned requests, durable saved result before checklist completion, fresh attempt directories, and collection outcome separate from cleanup. [Current collector direction](../ACTION/wf-scrapper-abm/COLLECTOR_SIMPLIFICATION.md), lines 20–35.

Discovery does not execute collection. Metadata does not complete a full-content task. Preserve partial/error bodies actually returned, record unavailable results, and never treat HTTP200/headers as proof of useful content or Python body receipt. All advertised REST pages fetched does not mean complete record coverage when totals disagree or IDs duplicate. [October5 incomplete full-stream attempt](response_2026-10-05_201927_planned-close-live-verification.md), lines 10–38; [Later run does not prove older counter path fixed](response_2026-10-03_234344_deadline-live-retest.md), lines 1–8.

**Worked example:** the old full-stream run obtained all 18 media pages but 1661/1753 unique records and exited 2 after unconfirmed teardown aborts. The first selected three-page plan later completed with empty REST scope. Both facts stand; do not combine their totals or rewrite the old run. [October5 incomplete full-stream attempt](response_2026-10-05_201927_planned-close-live-verification.md), lines 30–38; [First human-selected three-page collection](response_2026-10-11_203505_first-selected-collection.md), lines 1–17.

**Proposed improvement:** record the request budget's unit explicitly—planned page/REST calls, redirect hops, passive browser events and HTTP/wire requests are different units. Keep measured work/cleanup/storage beside the actual configured limit; do not turn an estimate into a ceiling.

## 4. Review — compare claims with source facts

**Demonstrated:** Tony chooses rows/stable IDs from the exact saved inventory. Labels are referring-page evidence, not verified destination titles. Generic CTA/ellipsis text cannot overwrite a meaningful heading. The earlier nine-label success claim was explicitly withdrawn when its weak oracle missed punctuation-only labels. All nine corrected labels were then checked against the actual saved h2 text. [Exact nine-label correction](response_2026-10-11_001956_label-cleanup-tony-choices.md), lines 1–33.

Review usefulness, provenance and limits, not exit status alone. In Prepare, compare the chosen HTML subtree with Markdown headings, paragraph/list order and meaningful links. Separate source facts from interpretation; keep absent, empty and null distinct. Do not transform a content gap into a plugin diagnosis or approve scope from a recommendation.

**Worked example:** Agency Services is a six-card category listing, not a service-detail page. Andromeda has seven source paragraphs, 15 list items and six headings. A separately dated REST post 11945 contains empty content; substantive HTML remains substantive. [Prepare v0.1 first sample](response_2026-10-11_210309_prepare-v01.md), lines 9–27.

**Proposed improvement:** use independent source-derived expectations for each new extraction boundary, including legitimate sparse/embedded pages. “Not Read Post,” “HTTP200,” or “looks plausible” are insufficient oracles.

## 5. Repair — narrow the mechanism before changing the product

**Demonstrated:** scoped repairs retained pre-fix failures, used real loopback Chromium where the boundary required it, inspected native IDs/event order, and ran affected checks/regression/Capture comparison against the same final source. Local mechanisms were separated from uncertain live causes. Expected outputs were not approved merely because regeneration produced them. [Local timeout repair and missing counters](response_2026-10-03_184524_local-sitemap-timeout.md), lines 3–8; [Local planned-close proof and limits](response_2026-10-05_194847_planned-close-repair.md), lines 5–45.

Record failed mechanism, expected/actual result, request/operation identity when available, owner-approved repair scope, source/test diff and reproduction. A command-intent diagnostic is not a transport send or successful reply; server receipt is not a precise wire-dispatch timestamp. Preserve first STOP and failed evidence. No scope relaxation, retry, identity switch or new live allocation follows automatically.

**Worked example:** local planned-close fixtures proved certain abort acknowledgements before close. The subsequent live run still had two unconfirmed late aborts. Engineering proof remained useful but did not erase the live finding. The active collector was later simplified by explicit direction, not by blanket protocol-error suppression. [Local planned-close proof and limits](response_2026-10-05_194847_planned-close-repair.md), lines 65–75; [October5 incomplete full-stream attempt](response_2026-10-05_201927_planned-close-live-verification.md), lines 30–38.

**Proposed improvement:** decide whether a defect belongs to active scope, retained experimental history or future maintenance before starting another repair. Retiring a path is an architectural disposition, not evidence that its historical failures passed.

## 6. Handoff — make review possible outside chat

**Demonstrated:** save a dated response; package readable inputs and results with START_HERE, file/hash inventory and a requested reviewer decision. Include exact source identity, commands/exits, environment from the actual run, result/coverage distinctions, reproduction, gaps and live allocation usage. List each file separately. Reference excluded raw/bulk evidence precisely; do not pretend it is bundled. [Growth Call bounded follow-up](response_2026-10-13_223736_growth-call-follow-up.md), lines 40–53.

Keep engineering claims and independent QA results distinct. A hash-valid package can still be incomplete. Source timestamps, publication dates and preparation dates are different. An accepted task must cite the actual scope and approval provenance; no fabricated certificate or session appointment.

**Proposed improvement:** check new package links/hash inventory before delivery and explicitly inventory archived support links that target excluded or genuinely missing material. Reuse one factual record rather than duplicating acceptance/QA ledgers. [QAM workflow and separate owners](../ACTION/wf-scrapper-abm/QAM/README.md), lines 30–46.

## 7. Closeout — decide what can truthfully be closed

**Demonstrated here:** selected captures, offline preparation and the bounded Growth Call task have accepted evidence. **Not demonstrated:** the full independent QAM campaign or original final ABM Gate Q. No factory-speed verdict is measured.

For a demonstration closeout, record accepted scope/results, source identity, limitations, owned finding dispositions, retained evidence and remaining decisions. Keep uncertified original obligations pending/parked; never turn not-run criteria into PASS or invent waivers.

For a future **formal** closeout under the existing QA contract: Engineer handoff → Tony candidate commit/QA branch → independent Q1 plan binding → SOL decision → Q2 → adjudicated scoped repairs/re-pin/retest → Tony's approved cleanup and QA acceptance **before Gate Q** → exact SOL certificate → required independent Astra/fresh-Fable reviews, dispositions/RRM/retest → JARVIS closeout carrying the certificate → Tony integration. Cold-read and whole-app CLI obligations stay distinct. This workflow is prescribed in the packet but not forward-tested in this campaign. [Canonical QA plan and closeout](../ACTION/wf-scrapper-abm/QA/MASTER_QA_TEST_PLAN.md), lines 63–90.

No agent stages/commits/branches/deletes automatically. Do not run full QA just for documentation cleanup. Product/contract/test changes need impact assessment and affected retest under approved scope. Deployment stays out of scope. The product verdict, engineering-demo verdict and workflow-pilot verdict are separate. [QAM checkpoint and pilot measures](../ACTION/wf-scrapper-abm/QAM/STATE.md), lines 45.

## 8. Operating guide — DECIDE → COLLECT → PREPARE

These are **syntax/reference examples, not commands executed by this draft and not new live authority**. Use the approved target/scope and NEW destinations; preserve originals. Normal browser resources and redirects are additional traffic.

### DECIDE: bounded discovery, then exact human choices

Choose `--mode sitemap` or `--mode default` explicitly; no silent switch. Default mode reads a bounded number of pages to discover links. Sitemap mode reads the approved sitemap/robots sources; live proof of the old controller is not proof of the new DECIDE sitemap path.

```bash
# Only with a separate authorization for this bounded recon scope.
venv/bin/python -m recon_pipeline.decide recon \
  --mode default --url https://cyberizegroup.com/blog/ \
  --out outputs/recon/NEW_REVIEW \
  --gap 5 --max-requests 4 --max-pages 1 --max-depth 0 \
  --max-rest-pages 1 --per-page 1 --max-candidates 100 --max-seconds 180
```

Read `inventory.json` and its numbered Markdown together. Public WordPress types use `/wp-json/wp/v2/types` without `_fields`; locally extract type properties. Individual pages/posts review responses use projected metadata. Advertised totals are not enumerated records and do not imply permission for full content/media. No root `/wp-json/` enumeration. [DECIDE operating instructions](../ACTION/wf-scrapper-abm/DECIDE.md), lines 1–26; [REST type-map repair and three-call sample](response_2026-10-10_195853_recon-types-label-fixes.md), lines 10–38.

When Tony chooses, bind the exact saved version; unmentioned rows stay undecided. Stable IDs survive ordering, while row numbers apply only to that version. Reject unknown/conflicting choices. The recorded actor string is not authentication. A recommendation/example is not approval.

```bash
# Historical first-batch pattern; new paths and actual choices required.
venv/bin/python -m recon_pipeline.decide select \
  --inventory agent_docs/RESPONSES/response_2026-10-11_001956_label-cleanup-tony-choices_review/inventory.json \
  --include-html 1 --include-html 3 --include-html 9 --by "Tony Stark" \
  --out outputs/reviews/NEW_DECISION.json
venv/bin/python -m recon_pipeline.decide export \
  --inventory agent_docs/RESPONSES/response_2026-10-11_001956_label-cleanup-tony-choices_review/inventory.json \
  --decision outputs/reviews/NEW_DECISION.json --out outputs/reviews/NEW_PLAN.json
```

Export keeps HTML and REST separate and does not collect. One post means its evidenced single-item endpoint, not all posts. Whole REST pagination requires explicit approval and `paginate/max_pages` scope. For an architect-requested URL outside an old review—as Growth Call was—record a new explicit one-URL plan; do not invent an old row/ID or rerun recon unnecessarily.

### COLLECT: explicit plan, durable results, explicit recovery

An HTML-only plan is `{"pages":["https://cyberizegroup.com/growth-call/"],"rest":[]}`. Inspect for already valid completed evidence first; do not refresh it for reassurance.

```bash
# Growth Call's approved one-call pattern; NEW paths shown, not a new allocation.
venv/bin/python -m recon_pipeline collect \
  --plan outputs/selections/NEW_EXPLICIT_PLAN.json \
  --collection outputs/collections/NEW_COLLECTION \
  --gap 5 --max-requests 1 --max-seconds 180 --max-bytes 20000000

# Authorized recovery only: skips valid completed body/metadata hashes.
venv/bin/python -m recon_pipeline resume \
  --collection outputs/collections/EXISTING_COLLECTION \
  --gap 5 --max-requests 1 --max-seconds 180 --max-bytes 20000000

# Queue explicit additions offline; then resume within the approved scope.
venv/bin/python -m recon_pipeline add \
  --collection outputs/collections/EXISTING_COLLECTION \
  --plan outputs/selections/NEW_ADDITIONS.json
```

Missing/failed/interrupted results remain eligible; a refusal does not authorize a retry. Refresh successful items only explicitly, retaining old attempts; changed paginated generations use a new collection. `add` queues without traffic. Live no-op resume was demonstrated; interrupted recovery/addition cases were locally exercised, not claimed as live-tested. [Two-item live collection and no-op resume](response_2026-10-07_194146_selected-collector-live.md), lines 69–81; [Simple collector local engineering checks](response_2026-10-07_192033_simple-collector.md).

Use the existing checklist/result validator; historical `raw-v2` and its reader are a different format. CLI exit 0 means selected scope complete with no reported cleanup error; it does not prove child iframe/content/resource completeness. Exit 2 is partial/failure; exit 3 means selected completion with cleanup error; interruption has its own outcome. Record collection and cleanup separately. Current limits bound planned work, not every HTTP request: 10 MiB is checked after body receipt; cleanup gets a separate 10 s; persistence is a checked estimate with overhead, not the retired exact aggregate supervisor. [Current collector direction](../ACTION/wf-scrapper-abm/COLLECTOR_SIMPLIFICATION.md), lines 83–90.

### PREPARE: agent inspection, helpers, sources and useful questions

```bash
# Offline after a validated saved collection is supplied.
PYTHONDONTWRITEBYTECODE=1 venv/bin/python \
  agent_docs/SKILLS/web-recon-prepare/scripts/prepare_saved.py \
  --collection outputs/collections/EXISTING_COLLECTION \
  --out outputs/prepared/NEW_PREPARED_PACKAGE
```

Follow the [Prepare skill](../SKILLS/web-recon-prepare/SKILL.md). Validate checklist references/body and metadata hashes before processing. Keep raw evidence unchanged; the helper extracts main Markdown, separate boilerplate and source index. The **agent** checks the boundary and authors `ARCHITECT_BRIEF.md`/`GAPS_AND_REQUESTS.md`; the helper alone is not the finished architect package.

Preserve useful headings/paragraphs/lists/links/CTAs; annotate observed versus inferred content types. Index original URL, capture save time, raw hash/file and CSS location. Historical REST stays separately dated; empty/missing/null stay distinct; image/deferred completeness is unverified. Recommendations authorize no new read, model API or form interaction.

**Growth Call lesson:** parent HTML can omit embedded-document content. The accepted follow-up had a useful title/SEO description and booking iframe, but no native main copy or inline form labels. Agent inspection corrected the **derived classification/presentation** in a separate output. **The helper was not repaired.** The child labels, slots and booking function remained unknown. It is legitimate to hand the architect an explicit gap instead of inventing fields or automatically fetching the iframe host. [Growth Call bounded follow-up](response_2026-10-13_223736_growth-call-follow-up.md), lines 25–37.

## 9. Proposed improvements — not implemented or adopted here

- A concise current-scope/terminal-state record to resolve stale QAM/legacy entry text without rewriting historical approvals.
- An iframe-aware Prepare classification/presentation enhancement, separately scoped and locally evidenced; no automatic nested-host collection.
- Stronger named content-fidelity oracles for sparse pages and embeddings, preserving native evidence and honest absent fields.
- A minimal handoff/link inventory and owned-finding closure checklist; packaging remains instruction-driven, not a claimed exporter platform.
- Pilot measurement of preparation/execution/review waits/repairs/cleanup/closeout only when that pilot is authorized. Record unexercised paths as untested; no numerical speedup claim and no broader factory-speed redesign now.
